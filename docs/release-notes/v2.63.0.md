## 새 기능

- 접근 목록의 허용 항목에 도메인(DDNS 이름 등)을 넣을 수 있습니다. NPG가 도메인을 주기적으로(기본 1분) 다시 조회해 지금 가리키는 주소만 허용합니다. 사설·루프백·예약 주소와 Cloudflare 주소는 허용하지 않고, CGNAT(100.64.0.0/10, Tailscale 등)는 허용합니다.
- 도메인이 갑자기 다른 곳을 가리키면(CNAME 대상 변경, 비어 있다가 예전에 없던 주소로 돌아옴, 하루에 너무 잦은 변경) 확인할 때까지 그 도메인을 막고 알림을 보냅니다. 접근 목록에서 "다시 허용"으로 확인합니다. 알림은 알림 설정에서 "도메인 항목 검토 필요"·"도메인 항목 변경 미반영"을 구독한 채널로만 갑니다.
- 설정 → 보안 → 도메인 항목(DDNS): 조회 주기, 반영 간격, 유예, 한도와 도메인별 상태, "지금 다시 적용".
- 이전 버전에서 IP 대신 이름으로 저장된 접근 목록 항목은 예전처럼 허용이면 아무 효과가 없고 거부면 모두를 막습니다. 이제 그 목록을 다시 저장할 수 있고, 허용 항목은 "도메인으로 옮기기"로 도메인 항목으로 바꿀 수 있습니다.

## 알아둘 것

- 이전 버전으로 되돌리면 도메인 항목은 그 접근 목록에서 "모두 거부"로 적용됩니다(IP 항목은 그대로). 이전 버전에서 그 목록을 저장하지 않았다면 다시 이 버전으로 올릴 때 도메인 항목이 돌아옵니다. 다만 유예 기간(기본 하루)보다 오래 이전 버전에 있었다면 처음에는 막혀 있다가, 같은 주소면 몇 분 안에 다시 허용되고 다른 주소면 "다시 허용"으로 확인해야 합니다.
- 이전 버전에서 그 목록을 저장했거나 이 버전의 백업을 이전 버전에 복원했다면, 도메인 항목은 평범한 "모두 거부" 규칙이 되어 다시 올려도 돌아오지 않습니다. 이 버전으로 올린 뒤 그 규칙을 지우고 도메인을 다시 넣으세요. 그 규칙이 있는 동안에는 도메인을 넣을 수 없습니다.
- 이전 버전에 있는 동안 fail2ban이 상대를 차단했다면, 그 차단은 다시 올린 뒤에도 차단 시간이 끝날 때까지 남습니다.
- 도메인 항목이 있는 접근 목록을 쓰는 호스트에서는 그 목록이 막은 클라이언트의 403을 fail2ban이 세지 않습니다. 상대의 주소가 바뀌는 동안 차단되지 않게 하기 위해서입니다.

## 고침

- Dynu DNS 인증서 발급이 일부 Dynu 네임서버가 응답하지 않을 때 실패하던 문제, Cloudflare가 아닌 제공자에도 Cloudflare 권한 안내가 나오던 문제. Dynu는 이제 레코드가 보일 때까지 도메인마다 최대 10분 기다린 뒤 실패합니다.

## New

- Access list allow rules can hold a domain (a DDNS name, for example). NPG looks it up again on a schedule (every minute by default) and allows only the addresses it points to now. Private, loopback, reserved and Cloudflare addresses are never allowed; CGNAT (100.64.0.0/10, Tailscale and the like) is.
- When a domain suddenly points elsewhere (its CNAME target changes, it comes back from empty with an address it never had, or it changes too often in a day), NPG blocks it and sends an alert until you confirm it with "Allow again" on the access list. Alerts go only to channels subscribed to "Domain entry needs review" and "Domain entry change not applied" in notification settings.
- Settings → Security → Domain entries (DDNS): check interval, apply gap, grace period and limits, the state of every domain, and "Apply now".
- Access list rules an older version saved with a name instead of an IP: an allow still does nothing, and a deny still blocks everyone, as before. The list can now be saved again, and "Move to domain" turns such an allow into a domain entry.

## Good to know

- If you go back to an older version, domain entries act as "deny all" in their access list (IP rules are unaffected). If the list is not saved on the older version, upgrading again brings the domain entries back; after more than the grace period (a day by default) on the older version they start blocked, and a domain still at the same address is allowed again within minutes, while one at a new address needs "Allow again".
- If the list is saved on the older version, or a backup of this version is restored there, each domain entry becomes a plain "deny all" rule and does not come back on upgrading. After upgrading, delete that rule and add the domain again; a list with that rule cannot take a domain.
- If fail2ban banned a partner while the older version ran, that ban stays after upgrading again until its ban time ends.
- On hosts whose access list has domain entries, fail2ban no longer counts the 403s of clients that list blocks, so a partner is not banned while its address changes.

## Fixed

- Dynu DNS certificates failed to issue when some Dynu nameservers did not answer, and providers other than Cloudflare were shown Cloudflare's permission advice. Dynu now waits up to 10 minutes per domain for the record to show before it fails.
